# Golden vectors: cross-language conformance for the STR core

The C++ core (`firmware/lib/str_core/`) and the Python reference
(`sim/python/pistr_sim/control/str.py`) must agree bit-for-bit in structure and to
`1e-6` relative in value. This directory holds the fixture that proves it.

Owner: **Lead**. Do not regenerate these files from inside a feature branch without
re-running both sides; a stale fixture is worse than no fixture.

## Format

Plain CSV, not JSON. Reason: the C++ test must parse it with the standard library
only, and a hand-rolled JSON parser is exactly the kind of code that hides bugs in a
conformance test.

`step_response_case.csv`:

```
# generated by sim/python/tests/generate_golden.py -- do not edit by hand
# spec: docs/CONTROL_SPEC.md §8  schema: 1
# config: h=0.04 order=2 p_max=5 lambda=0.99 mu=0.0 zeta=0.7 wn=5.0 percent=0.75
# tolerance_rel=1e-6
t,y_des,y,u,u_actual,theta0,theta1,theta2,theta3
0.000000,0.000000e+00,0.000000e+00,0.000000e+00,0.000000e+00,...
```

* One row per **controller tick** (`h = 0.04 s`), not per integration step.
* `theta0..theta3` is `theta_hat` after the update for that tick (`order=3` files
  carry `theta0..theta5`).
* All values in SI / rad / PWM-differential units, 12 significant digits.
* Lines starting with `#` are metadata and must be skipped by both readers.

## The scenario (normative, from CONTROL_SPEC §8)

Mode II, `h = 0.04 s`, `dt = 1e-3 s`, `Pmax = 5`, `lambda = 0.99`, `mu = 0`,
`zeta = 0.7`, `wn = 5`, `percent = 0.75`, initial `roll = 0.02 rad`, reference is a
roll step to `0.10 rad` at `t = 1.0 s`, duration 3 s, no sensor noise.

The plant used to generate `y` is the **same simple ARX model** on both sides
(`theta_true` fixed, written in the fixture header), not the Python quadrotor plant.
That keeps the test a test of the *controller*, not of a physics port.

## How each side uses it

* Python: `sim/python/tests/test_golden_conformance.py` recomputes the trace and
  asserts it equals the fixture (guards against accidental regeneration drift).
* C++: `tests/cpp/test_golden.cpp` reads the CSV, replays `y_des`/`y` through
  `str_core`, and asserts the command and parameter sequence match.

Both tests skip with a clear message if the fixture is absent — never fail silently.

## How it is actually executed (important)

Some sandboxes refuse to execute freshly built Mach-O binaries (`SIGKILL` on
start-up, reproducibly, even for a hello-world). This repository therefore exposes
the conformance check through the shared library instead of a stand-alone tool:

```
python3 -c "import ctypes; lib=ctypes.CDLL('build/libstr_core_verify.dylib'); \
            print(lib.str_core_run_tests(b'golden'))"     # 0 == PASS
```

`tests/golden/compare.py` remains as the *debugging* driver (it shells out to
`str_core_trace`) and prints a per-column table; use it when a check fails and you
need to see which tick diverged. CI should call the ctypes entry point, not the
binary.
